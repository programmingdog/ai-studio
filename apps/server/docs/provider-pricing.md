# WagaAI 实时价格

后台「设定 → AI 供应商」的供应商卡片新增「查看实时价格」。目前仅 `code=wagaai` 接入，其他供应商显示暂不支持。必须有启用的 API Key；禁用的 Key 不会使用。查询使用首个启用密钥（按创建时间、ID 排序），其名称会显示在弹窗，方便辨别渠道策略差异。

## 管理接口

`GET /api/v1/admin/providers/:providerId/pricing`

需要管理员登录和 `providers.manage` 权限，响应设置 `Cache-Control: no-store`。

查询流程：

1. 从数据库读取供应商 HTTPS 网关地址和加密 Key，在后端解密。
2. 请求 `/v1/skills/models`，不按类型筛选；补充目录外的本地已配置模型。
3. 对每个模型请求 `/v1/skills/models/{model_name}/pricing`，不加 `status=active`，保留暂停渠道。
4. 按完整 `model_code` 精确对应本地模型别名。同一个代码的多个本地配置均可显示价格。

上游参考：[WagaAI 价格文档](https://wagaga.cc/apidoc#common/model_pricing)；详细参数以供应商网关 `/v1/skills` 中 `list_models` 和 `model_pricing` 端点说明为依据。

并发数限制为 6，单次请求 15 秒超时、整体查询 120 秒截止，单个响应最大 8 MiB。只合并同时发生的查询，之后点击会重新访问上游。模型目录失败时返回错误；单个模型失败时返回该模型的 `error`，其他结果仍可使用。不会把上游原始错误正文或 API Key 回传前端。

## 展示与定价边界

- 弹窗列出上游目录及本地补查模型，可搜索模型名称/代码/别名、筛选本地配置、分页和刷新。
- 展开模型可查看所有渠道的基础价、最低价、Token 输入/输出价、折扣和参数选项价格（包括分辨率、时长等上游实际返回的参数）。渠道标记运行、暂停及 Key 白名单情况。
- 模型卡片展示前两个渠道的价格摘要，优先展示运行且未被 Key 白名单排除的渠道，全部明细在弹窗中。
- 价格为供应商返回的原始值，保留零价格，不推测接口未提供的币种/Token 单位，不混合不同计费方式计算最低价。参数选项价格也不直接相加。
- `GET /pricing` 始终只读。后台查询按钮使用 `POST /pricing/sync`：配置中心开启自动定价后更新 `credit_cost` 及分辨率积分；关闭时只查询。不改变用户余额或已创建任务，也不产生生成任务。
- 价格仅为当前页面会话的查询快照，附带时间。关闭弹窗或切换供应商不会清空；刷新页面、离开供应商页面或保存配置后需要重新查询。刷新失败会明确标注仍在显示旧结果。

2026-08-30 验证时目录返回 141 个模型，本地配置的 15 个模型均查询成功。上游对 `kimi/kimi-k2.7-code-highspeed`、`kimi/kimi-k2.7-code`、`stepfun/step-3.7-flash` 的价格请求返回 HTTP 404；前端按模型标记失败，不视作零价格。

## 人民币与积分比例、自动定价

配置中心顶部提供独立的「积分与人民币比例」配置，存于 `model_credit_pricing_config`（迁移 `016_credit_pricing_config.sql`）。初始示例 `cny_per_credit=0.1`，自动定价默认关闭，不会因升级而覆盖旧定价。

- 管理员确认 WagaAI 的算力与人民币为 1:1，渠道选价使用运行中、未被当前 Key 白名单排除、模型对 Key 可用的最低可换算报价。
- `积分 = ceil(人民币单价 / cny_per_credit)`，最低 1、最高 100000 积分；超上限时跳过而非截断。比例允许 6 位小数，范围 0.000001～1000000。
- 图片按已配置分辨率换算每次积分。视频的按秒报价直接换算；按次报价必须有明确时长，再换算每秒积分。固定 `omni_flash-10s` 使用其固定 10 秒。
- 复用生成请求的分辨率匹配规则，保持接口值大小写和像素档位一致。每档独立计算最低参数组合，不将不同选项的 `final_price` 相加；保留 `min_price` 底价约束，不重复应用已包含的时段折扣。
- 按 Token 的报价不能作为每次/每秒费用。当前账务仍使用固定按次/按秒消费，缺少 Token 用量换算规则的模型/渠道不参与自动换算；Token 专用模型保留原积分并显示原因。混合渠道仅比较可换算的按次/按秒渠道，并明确提示。
- 无可用渠道、未开放或不支持的分辨率、上游查询失败、未知币种及无法识别的时长/参数联动约束都会跳过并保留原价，不设置为零。
- 最低价只覆盖最低参数组合，参考图超额、输入参考视频等独立附加成本不包含在报价中；不保证实际任务一定命中该最低渠道，也不会更改 WagaAI API Key 的渠道策略。
- 分辨率表中计算成功的档位逐项更新；只有某模型全部档位都可换算时才同步其 `credit_cost` 为最低档积分。不会新增、删除分辨率。

启用自动定价后，保存比例会更新已接入且启用的供应商；供应商页面点击查询/刷新也会同步该供应商积分，并重新加载模型列表。不是定时任务，不在客户端发起生成时访问价格接口。旧任务继续使用创建时锁定的估算积分，新任务读取更新后的分辨率价格；充值套餐和用户余额不受影响。

新增接口：

- `GET /admin/configs/credit-pricing`：读取比例、开关、版本及最近报告，需要 `configs.manage`。
- `PATCH /admin/configs/credit-pricing`：保存 `{cny_per_credit, auto_sync, revision}`，开启时同步；需要 `configs.manage` 和 `providers.manage`。
- `POST /admin/configs/credit-pricing/sync`：按已保存比例刷新全部已接入供应商，需要上述两个权限。
- `POST /admin/providers/:providerId/pricing/sync`：查询价格并按开关同步，需要 `providers.manage`，返回价格与 `credit_sync` 报告。

比例保存使用乐观版本检查。每个供应商的模型及分辨率更新与审计日志在同一事务提交；提交前检查比例、模型配置和所选供应商/Key 是否改变，拒绝过期查询覆盖新编辑。单供应商并发同步返回冲突，避免重复执行。报告列出旧值、新值、人民币最低价、采用渠道、参数及跳过原因。

验证包括换算规则、整数舍入、分辨率/像素档位、参数组合、按次视频换算每秒、Token 跳过、版本及模型/Key 并发冲突、关闭自动定价的只读行为、事务审计。真实数据库写入验证已回滚并确认原比例及所有定价保持不变。
