# 客户端模型扣费与确认

客户端积分提示使用通俗文案，例如“本次二创需要扣 4 积分”“确认并开始（4 积分）”“取消，不扣分”。提示不展示模型名称、系数、冻结、结算等术语；图片/视频选择页仍保留方案名称、清晰度和积分，方便选择。技术计费规则保持不变：失败退款，已生成内容需要调整时仍计费，并在确认前用简短文字说明。

文案测试：`npm run test:credit-copy --workspace @aivs/desktop`。

## 调用核对

| 操作 | 是否调用大模型 | 积分规则 |
| --- | --- | --- |
| 解析结果另存 TXT、使用解析结果创建项目 | 否，仅本地解析、存储 | 0 积分 |
| 已生成的二创结果保存为新项目 | 否，仅本地存储 | 0 积分 |
| 二创生成剧情与分镜 | 是，服务端默认文本模型 | 文本模型基础积分 × 文本类型系数 |
| 创意大纲、分集、角色场景设定、分镜、Agent 每轮规划 | 是，服务端默认文本模型 | 每次调用独立确认并结算 |
| 视频理解（公网 URL / 本地压缩上传） | 是，服务端默认视频理解模型 | 模型积分 × 视频理解类型系数 |
| 角色、场景、分镜图片 | 是，用户选择的服务端图片模型 | 所选分辨率积分 × 图片类型系数，每张分别计费 |
| 分镜视频 | 是，用户选择的服务端视频模型 | 所选分辨率每秒积分 × 请求秒数 × 视频类型系数 |

自动工作流只在启动前确认一次。统一选择图片和视频方案及清晰度，按缺少的场景图、角色图、分镜图、分镜视频计算分项和总积分；已有资产不重复计费，最后合成免费。确认后按该清单自动执行，不再逐项弹窗，也不显示低积分购买提醒。其他手动生成仍须确认；自动制作期间手动请求的确认延后显示，不会默许扣费。

本次授权保存在项目数据库中，绑定账户、项目、目标、模型、清晰度、时长和每项积分。相同任务恢复使用原幂等键，成功或结果不明的内容不能用新任务再次消耗预算；服务端确认失败且冻结积分已释放后才恢复该项重试额度。费用变化、新增内容、余额不足、结果或退款无法确认时，在进度中说明并停止，不弹窗、不追加扣分。重启可恢复尚未提交的已授权项；未确认结果的已提交项尽量按原任务查询，无法恢复时安全停止。完成或停止后撤销授权。

## 确认与结算流程

1. 客户端调用只读 `POST /api/v1/tasks/quote`，取得可用模型、别名、分辨率、请求时长及含系数的精确积分。报价不调用供应商、不写积分流水。
2. 手动生成进入账户绑定的待确认队列；自动工作流使用启动前确认并持久化的清单，不进入逐项弹窗。凭据读取由后台线程处理。取消、超时、账户切换均不发起未授权的模型调用。
3. 用户确认后提交报价中的 `provider_model_id` 和 `expected_credits`。服务器再次计算，价格变化时拒绝提交，要求重新确认；客户端不能自行决定扣费金额。
4. 服务端检查可用余额，冻结积分，调用供应商，成功结算、失败释放。重复的幂等请求不会重复创建扣费调用。
5. 供应商已经成功返回，但客户端解析或内容校验失败，原调用仍计费。手动纠错、重做须再次确认；自动工作流遇到这类情况安全停止，避免重复扣分。服务端已确认退款的自动任务可在原额度内重试。

取消仅取消当前待确认批次，不撤销已确认、已提交的调用。旧版直连生图/视频任务停止执行，需要重新选择服务端模型；旧版客户端本地积分配置只作历史参考，不参与真实计费。

### 低积分购买提醒

已登录用户的可用积分（扣除冻结部分）低于 10 分时显示购买套餐提醒，恰好 10 分不触发。余额每 15 秒检查一次，支付到账和扣费确认引起的余额刷新也会更新提醒。未登录、余额未知或读取失败不按 0 分处理。

已有操作、扣费确认或支付弹窗时延后提示；点击“稍后再说”后保留右下角购买入口，同一轮持续低余额不重复弹窗。余额回到至少 10 分后再次跌破时重新提醒；退出后重新登录或切换账户独立判断。点击“购买积分套餐”直接进入账户中心的“积分与购买”，不自动创建订单或扣款。

提醒规则测试：`npm run test:low-credit --workspace @aivs/desktop`。独立无订单 UI 测试页：`/test/low-credit-reminder.html`。

- 服务端测试：`npm run test:credit-confirmation --workspace @aivs/server`；已有分辨率、系数、动态价格和账本测试继续运行。
- 原生测试：`cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml --offline --lib -- --test-threads=1`。
- UI 测试页：运行桌面 Vite 开发服务后打开 `/test/credit-confirmation.html`，覆盖正常、积分不足、余额读取失败、0积分模型。该页仅渲染真实确认组件，不访问平台账户、不调用模型、不扣分，不进入生产构建入口。
- 服务端和桌面客户端需同时更新并重启，无新增数据库迁移。后台需要配置启用且可用的默认文本模型。Agent 工具调用目前需要 OpenAI 兼容文本模型；Gemini 文本协议可用于二创和创意步骤，但不支持此 Agent 的工具协议，遇到时在扣费前拒绝。
